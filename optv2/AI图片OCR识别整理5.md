## 1. 问题

用户反馈：数据接入页面看起来没有自适应，"上传并开始解析"按钮看起来无法点击。

当前页面主要问题（`frontend/src/pages/IntakeView.vue`）：

1. 根容器 `.intake` 设置了 `max-width: 960px`，宽屏下页面没有铺满内容区。
2. 上传按钮在没有选择文件时禁用是合理的，但页面没有明确告诉用户"先点击/拖拽选择文件，按钮才会启用"。
3. 操作区只是普通按钮行，视觉上不像一个明确的"下一步"区域。
4. 文件台账表格在窄屏下没有横向容器，容易挤压。
5. 上传组件没有同步 `on-remove`，用户从文件列表移除文件后，内部 `pending` 仍可能保留旧文件，导致按钮状态和真实待上传文件不一致。

### 1.1 已识别的明确 bug

低端 agent 必须把本节当成 bug 修复要求，不要只当成体验优化。

#### BugA：移除文件后仍可能上传旧文件

症状：

1. 用户点击上传框选择一个文件。
2. 页面按钮变为可点击。
3. 用户在 Element Plus 文件列表里移除这个文件。
4. 视觉上文件似乎已经移除，但前端 `pending` 数组仍可能保留旧文件。
5. 按钮状态和真实 UI 不一致，用户可能上传一个已经从列表里删掉的文件。

原因：原代码只实现了 `onChange(file)`，没有给 `el-upload` 绑定 `on-remove`。Element Plus 内部文件列表变化后，业务状态 `pending` 没有同步删除对应文件。

必须修复：

```vue
<el-upload
  ref="uploadRef"
  :on-change="onChange"
  :on-remove="onRemove"
/>
```

并实现：

```ts
function onRemove(file) {
  const name = file.raw?.name || file.name
  pending.value = pending.value.filter((f) => f.name !== name)
}
```

验收：

- 删除该文件后，按钮必须变回"请先选择文件"。
- 选择 1 个文件后，按钮显示"上传并开始解析"。
- 删除文件后点击按钮，不得上传旧文件。

#### BugB：上传成功后文件列表可能残留

症状：

1. 用户选择文件并上传。
2. 后端返回成功，任务进入解析。
3. 前端 `pending` 被清空。
4. 但 Element Plus 上传组件自己的文件列表可能仍显示旧文件。

原因：只清空了业务状态 `pending.value = []`，没有调用上传组件实例的 `clearFiles()`。

必须修复：

```ts
const uploadRef = ref()
```

上传全部成功后：

```ts
pending.value = []
uploadRef.value?.clearFiles()
```

验收：

- 上传成功后，上传文件列表清空。
- 按钮恢复为"请先选择文件"。
- 当前任务出现在"任务/识别结论"区域。

## 2. 本次目标

只改用户体验，不改上传解析能力。目标：

- 页面宽度适配工作台内容区。
- 上传区域明确告诉用户如何激活按钮。
- 未选择文件时按钮不要像"系统坏了"，而是表达"请先选择文件"。
- 已选择文件后按钮明显变为主操作。
- 表格区域在窄屏下可以横向滚动，不挤坏布局。

## 3. 不做什么

1. 不修改上传接口 `/api/v1/files`。
2. 不修改解析任务、SSE、轮询逻辑。
3. 不修改数据库。
4. 不增加新的上传流程步骤。
5. 不删除原有文件台账。
6. 不修改项目 `smart-material-system`。

## 4. 修改文件

只修改：`frontend/src/pages/IntakeView.vue`。

## 5. 实施步骤

### 步骤 1：上传卡片增加状态说明

在上传区域增加一个说明块：

- 已选择文件：显示"已选择 N 个文件，可开始上传解析"。
- 未选择文件：提示"请选择或拖拽文件，选择后才能上传并解析"。

### 步骤 2：按钮文案动态变化

按钮逻辑保持禁用条件：

```vue
:disabled="!pending.length"
```

但按钮文案改为：

- 未选择文件：请先选择文件
- 已选择文件：上传并开始解析

这样用户知道不是按钮坏了，而是缺少前置动作。

### 步骤 3：改善操作区布局

把按钮区域改成卡片底部操作条：

- 右侧显示主按钮。
- 左侧显示选择状态。
- 小屏幕下纵向排列。

### 步骤 4：页面宽度自适应

把 `.intake` 从固定 `max-width: 960px` 改为：

```css
.intake {
  display: flex;
  gap: 16px;
  flex-direction: column;
  width: 100%;
  max-width: 100%;
  box-sizing: border-box;
}
```

### 步骤 5：表格容器可横向滚动

给文件台账表格和高级详情表格外层加 `.table-wrap`：

```css
.table-wrap {
  width: 100%;
  overflow-x: auto;
}
```

### 步骤 6：同步上传文件移除和清空

给 `el-upload` 增加：

```vue
ref="uploadRef"
:on-remove="onRemove"
```

实现要求：

1. `onChange` 负责把新增文件写入 `pending`。
2. `onRemove` 必须从 `pending` 删除同名文件。
3. 上传全部成功后，必须执行 `uploadRef.value?.clearFiles()`，避免界面还显示旧文件。
4. 如果上传失败，不要清空 `pending`，方便用户重试。
5. `onRemove` 不允许只更新 Element Plus 自带文件列表，必须同步业务数组 `pending`。
6. `clearFiles()` 只能在上传全部成功后执行，不能放在 `finally`，否则失败时用户无法重试原文件。

## 6. 验收标准

1. 宽屏下页面不再卡在 960px 宽度。
2. 未选择文件时按钮显示"请先选择文件"，旁边有解释文案。
3. 选择文件后按钮显示"上传并开始解析"，并可点击。
4. 文件台账表格在窄屏不挤坏页面。
5. 从上传文件列表移除文件后，按钮状态同步变化。
6. 上传成功后，上传文件列表被清空。
7. 上传失败时，文件列表和 `pending` 不被强制清空，用户可以重试。
8. 上传、任务监听、进入规整逻辑不变。
9. `npm run build` 通过。
