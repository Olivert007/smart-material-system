# 物资规整筛选导出界面可执行计划

> 适用页面：/govern 的物资规整，或后续独立的"物资规整明细"页面
> 记录目的：先把业务需求、现状差距和修改方案写清楚，再进入代码实现。

## 1. 业务目标

物资规整界面应面向业务人员展示已规整后的物资台账，支持按物资种类和存放区域筛选，并导出当前筛选结果。

主要场景：

1. 物资盘点：按区域查看库存物资。
2. 台账整理：按物资种类整理维护材料、低值易耗品、备品备件、工器具等。
3. 物资核对：根据物资名称、物资编码快速定位记录。
4. 业务导出：导出当前筛选后的台账，不误导出全库。

## 2. 物资种类与筛选维度

### 2.1 物资种类

第一版固定支持以下业务枚举：

1. 维护材料
2. 低值易耗品
3. 备品备件
4. 公用工器具
5. 个人工器具

后续如果系统已有正式物资种类字典，应从字典加载，不在前端写死。

### 2.2 存放区域

区域来自已规整库存台账中的 `location` 字段，或后续区域主数据。

示例：

1. 仓库A
2. 车间1区
3. 维修班组
4. 工具房
5. 中心库

不允许用户手动输入不存在的区域。

### 2.3 关键字

支持按以下字段模糊查询：

1. 物资编码
2. 物资名称

## 3. 当前系统现状

### 3.1 已具备能力

**fact_inventory**（已有库存台账字段）：

- category
- location
- stock_qty
- unit
- source_release_id
- row_key

**v_browse_inventory**（已将库存事实表与 dim_material 关联，能展示）：

- material_name
- spec
- unit
- region
- category
- location
- stock_qty

**BrowseView.vue**：

- 已有分页表格和导出入口。
- `/api/v1/browse/{table}` 已支持整表分页浏览。
- `/api/v1/export/table/{table}` 已支持整表 CSV 导出。

### 3.2 当前差距

1. BrowseView.vue 是通用表浏览器，不是业务专用的物资规整界面。
2. 当前浏览接口只支持 limit/offset，不支持物资种类、区域、关键字筛选。
3. 当前导出接口只按整表导出，不会跟随页面筛选条件。
4. 当前导出格式是 CSV，不是用户需求里的 Excel。
5. 当前表格列由后端字段动态生成，无法保证物资规整场景下的固定业务列顺序。
6. 当前"数据规整→物资规整"偏治理待办，不是全量物资台账筛选页面；两者职责需要区分。

## 4. 推荐页面定位

建议不要直接把现有"物资规整"待审队列改成台账浏览页，否则会混淆两类业务：

- **数据规整→物资规整**：处理待匹配、待合并、待确认的物资主数据问题。重点是治理动作。
- **数据成果/规整明细→物资规整明细**：展示已规整后的物资台账。重点是筛选、查看、导出。

第一版可在"数据成果→规整明细"中优先落地，因为该页已经承载"规整后业务库视图"。

如果用户坚持放在"数据规整"页面，应在 Tab 内明确区分：

- 待处理物资
- 物资台账

避免把"治理待办"和"台账浏览"放在同一个表格中。

## 5. 页面结构方案

### 5.1 页面头部

标题：

```text
物资规整
```

说明：

```text
展示已规整的物资台账，可按物资种类、存放区域筛选，并导出当前筛选结果。
```

操作按钮：

1. 刷新
2. 导出筛选结果

### 5.2 筛选栏

筛选项：

1. **物资种类**：多选下拉，默认全部。选项：维护材料、低值易耗品、备品备件、公用工器具、个人工器具
2. **存放区域**：多选下拉，默认全部。选项来自接口返回的区域列表
3. **关键字**：输入框，占位"请输入物资编码或物资名称"
4. **按钮**：查询 / 重置

筛选规则：

1. 不选择任何条件时，展示全量物资。
2. 物资种类和存放区域是组合筛选，关系为 AND。
3. 多个物资种类之间是 OR。
4. 多个区域之间是 OR。
5. 关键字命中物资编码或物资名称即可。

### 5.3 统计栏

筛选后展示：

```text
当前共查询到 XX 条物资记录
```

可选增强：

```text
维护材料XX条/低值易耗品XX条/备品备件XX条/公用工器具XX条/个人工器具XX条
```

统计必须与当前筛选条件一致。

### 5.4 表格字段

固定展示以下列：

1. 物资编码
2. 物资名称
3. 物资种类
4. 存放区域
5. 规格型号
6. 单位
7. 库存数量
8. 状态
9. 操作

操作：

1. 查看详情
2. 追溯来源（可复用现有追溯能力）

无数据提示：

```text
暂无匹配的物资数据，请调整物资种类或存放区域筛选条件
```

## 6. 后端接口方案

### 6.1 新增专用浏览接口

推荐新增：

```text
GET /api/v1/materials/standardized
```

参数：

1. categories：逗号分隔物资种类，可为空。
2. locations：逗号分隔存放区域，可为空。
3. q：物资编码或物资名称关键字，可为空。
4. limit：分页条数。
5. offset：分页偏移。
6. sort_by：排序字段，可选 material_code / material_name / stock_qty
7. sort_order：asc 或 desc。

返回：

```json
{
  "items": [],
  "total": 0,
  "summary": {
    "by_category": []
  },
  "filters": {
    "categories": [],
    "locations": []
  },
  "limit": 20,
  "offset": 0
}
```

### 6.2 新增筛选项接口

推荐新增：

```text
GET /api/v1/materials/standardized/filters
```

返回：

```json
{
  "categories": ["维护材料", "低值易耗品", "备品备件", "公用工器具", "个人工器具"],
  "locations": ["仓库A", "车间1区", "维修班组", "工具房"]
}
```

### 6.3 新增导出接口

推荐新增：

```text
GET /api/v1/materials/standardized/export
```

参数与浏览接口一致，但不需要分页参数。

导出规则：

1. 只导出当前筛选条件命中的结果。
2. 结果为 0 条时拒绝导出。
3. 默认导出 Excel；如果短期只能 CSV，页面文案必须明确为 CSV，不能写 Excel。
4. 文件名：物资规整_筛选结果_YYYYMMDD.xlsx

## 7. 前端修改方案

### 7.1 推荐新增组件

新增：

```text
frontend/src/components/MaterialStandardizedPanel.vue
```

职责：

1. 管理筛选条件。
2. 加载筛选项。
3. 加载分页数据。
4. 展示统计和表格。
5. 导出当前筛选结果。

### 7.2 页面挂载位置

优先方案：

```text
DataView.vue → 规整明细 → MaterialStandardizedPanel
```

保留原有通用 BrowseView，作为高级浏览或其他表浏览入口。

备选方案：

```text
GovernView.vue → 物资规整 → 增加「待处理物资/物资台账」二级切换
```

### 7.3 URL 状态

建议同步以下 query：

1. categories
2. locations
3. q
4. page
5. page_size

这样刷新页面后筛选条件不丢失，也方便分享筛选后的视图。

## 8. 权限与安全

1. 浏览接口只读。
2. 导出接口需要导出权限。
3. 导出必须走白名单字段，不允许前端传任意 SQL。
4. 筛选参数必须参数化绑定，不拼接用户输入。
5. 导出文件应做公式注入防护，沿用现有 CSV 安全逻辑。

## 9. 弹窗与提示文案

筛选无数据：

```text
暂无匹配的物资数据，请调整物资种类或存放区域筛选条件
```

导出确认：

```text
当前筛选条件共查询到【{number}】条物资记录，确认导出Excel？
```

导出无数据：

```text
当前筛选条件查询结果为空，不支持导出，请重新设置筛选条件
```

导出成功：

```text
导出任务已完成，文件开始下载
```

导出失败：

```text
导出失败，请稍后重试
```

## 10. 验收标准

1. 打开页面时默认展示全量物资台账。
2. 选择单个物资种类后，只展示该种类物资。
3. 同时选择多个物资种类后，展示任意已选种类物资。
4. 选择存放区域后，只展示该区域物资。
5. 同时选择物资种类和存放区域后，展示两者交集。
6. 输入物资编码或物资名称关键字后，表格按关键字过滤。
7. 统计数量与表格总数一致。
8. 分页切换后筛选条件不丢失。
9. 导出结果与当前筛选结果一致。
10. 筛选结果为空时不能导出。
11. 页面不展示 SQL、内部表名、内部物资ID 等技术信息。
12. 窄屏下筛选栏自动换行，表格不撑破页面。

## 11. 第一版实施建议

第一版按以下顺序实现：

1. 后端新增只读筛选查询接口，先返回 JSON 分页结果。
2. 前端新增 MaterialStandardizedPanel.vue，完成筛选、统计和表格展示。
3. 导出先复用 CSV 安全能力，但页面如未实现 Excel，不应写"Excel"。
4. 第二步再补 Excel 导出。
5. 最后决定是否将该能力放入"数据规整"，或保留在"数据成果→规整明细"。

## 12. 暂不处理

1. 物资种类主数据维护页面。
2. 区域主数据维护页面。
3. 用户级导出权限体系重构。
4. Excel 多 Sheet 模板导出。
5. 盘点差异回写流程。

## 13. 二次简化决策：默认先展示物资台账

用户反馈：页面仍然不够直达。站在业务用户角度，进入"数据规整"的高频目标不是先处理治理队列，而是查看已规整后的物资台账，并完成筛选、核对、导出。

### 13.1 当前问题

1. "数据规整工作台"默认先展示待处理事项，物资台账需要点击入口或通过 URL 参数进入。
2. 入口层级深，用户会认为页面偏后台治理。
3. 用户最核心动作"筛选物资→查看结果→导出"没有在首屏直接出现。

### 13.2 简化原则

1. 物资台账默认展示在数据规整首屏。
2. 待处理问题保留，但下沉为次要区域。
3. 字段规整、规则沉淀、待审队列、流水处理、库存对账统一作为高级治理入口，不在首屏打断业务查询。
4. 页面标题和说明改成业务语言，减少 AI、门禁、L1/L2/L3 等治理术语。

### 13.4 新验收标准

1. 打开 /govern 后，首屏可以直接看到物资台账筛选区。
2. 用户无需理解治理队列，也可以完成按物资种类、存放区域筛选。
3. 待处理问题仍可查看，但不抢占首屏主任务。
4. 高级治理入口仍能进入字段、物资、流水、库存对账处理页面。

## 14. 页面中英文混合问题记录

用户反馈：修改后的页面仍存在中英文混合问题。

### 14.1 问题表现

1. 当物资没有正式 material_code 时，后端用 material_id 兜底展示为物资编码，页面可能出现 "M-xxxx" 这类内部编号。
2. 业务页面文案中仍有 AI、"Excel" 等英文词。
3. 导出确认文案写"导出 Excel"，不够统一。

### 14.2 修复要求

1. 物资台账默认不展示 material_id、row_key、source_release_id 这类内部字段。
2. 物资编码没有正式编码时展示"未维护"或空值，不用内部 ID 兜底。
3. 查询关键字只面向业务字段：物资编码、物资名称。
4. 页面文案统一中文："AI"改为"智能建议"；Excel 改为"电子表格"或"表格文件"。
5. 详情和导出同样不暴露内部编号。

### 14.3 验收标准

1. 物资台账列表不再出现 "M-xxxx" 作为物资编码。
2. 导出确认文案为中文表达。
3. 首屏说明和待处理问题说明不出现不必要英文词。
