### 0.3 推荐 `docker run`（在你现有命令上补端口）

PoC 在你现有命令上补端口，且**映射到回环**（单机模式）；镜像与 `bash` 间须有空格：

```bash
docker rm -f vllm-omni-dev 2>/dev/null || true

docker run -d \
  --name vllm-omni-dev \
  --restart unless-stopped \
  --gpus all \
  --ipc=host \
  --shm-size=16g \
  -p 127.0.0.1:8000:8000 \
  -p 127.0.0.1:8001:8001 \
  -p 127.0.0.1:8002:8002 \
  -p 127.0.0.1:8010:8010 \
  -p 127.0.0.1:8080:8080 \
  -p 127.0.0.1:8091:8091 \
  -p 127.0.0.1:7861:7861 \
  -e HF_TOKEN="${HF_TOKEN:-}" \
  -e HF_HOME=/root/.cache/huggingface \
  -e OPS_TOKEN="${OPS_TOKEN:-changeme-set-me}" \
  -e ALLOW_LEGACY_INGEST=0 \
  -e ALLOW_FREE_QUERY=0 \
  -e OFFLINE_MODE=1 \
  -e LLM_FAST_ENDPOINT=http://127.0.0.1:8000/v1 \
  -e LLM_BIG_ENDPOINT=http://127.0.0.1:8001/v1 \
  -e LLM_EMBED_ENDPOINT=http://127.0.0.1:8002/v1 \
  -e LLM_CIRCUIT_FAILS=3 \
  -e LLM_CIRCUIT_COOLDOWN_SEC=60 \
  -e UPLOAD_MAX_BYTES=2147483648 \
  -e UPLOAD_MAX_EXTRACT_BYTES=524288000 \
  -v "$HOME/dev/models:/models:ro" \
  -v "$HOME/dev/projects:/workspace:rw" \
  -v "$HOME/dev/config/deploy:/config/deploy:ro" \
  -w /workspace \
  --ulimit memlock=-1 \
  --ulimit stack=67108864 \
  vllm/vllm-omni:v0.26.0-aarch64 \
  bash -lc "sleep infinity"
```

检查：

```bash
docker port vllm-omni-dev
# 期望含 8000、8001、8002（embed PoC）、8010、8080
```

> `docker start` 不能补端口，改映射必须 `rm` + 再 `run`。模型只读挂载；工程可写。

### 0.5 运行态验收（doc 17）

**设计目标**（`app/config.py`）：fast `:8000`、big `:8001`、embed `:8002`、API `:8010`。

**当前验收**以脚本输出为准（区分「设计存在」与「环境可用」）：

```bash
./scripts/start_dev_stack.sh                              # 启动顺序指引
PYTHONPATH=. python3 scripts/check_runtime.py | python3 -m json.tool
```

| `runtime_level` | 判定 | 可做什么 |
|---|---|---|
| `none` | API 未 ready | 不能演示 |
| `dev_ok` | API ready + Vite 可访问，三模型均未起 | 可演示前端开发态 |
| `stage1_degraded` | API 正常但模型不完整或名称不匹配 | 可演示，模型能力受限 |
| `full` | 三模型在线且 `configured_model` 与 served 名称一致 | 完整 Stage 1 验收 |

degraded 说明：embed 不可用时词法 fallback（`EMBED_FALLBACK_LEXICAL=1`）；big 不可用时复杂生成与 Text2SQL 终稿受限；fast 模型名不匹配时不得标 `full`。

## 1. 启动流程（全部 `docker exec`）

推荐：宿主机执行 `bash start_services.sh`（脚本内容 = 下列命令；实现阶段落盘到工程根）。

### 1.1 启动 vLLM

```bash
docker exec vllm-omni-dev bash -lc 'pkill -9 -f "vllm serve" || true; sleep 1'

# 过渡 fast=7B：仅单实例调试可用 0.85；与 big 共存必须下调（01 §3.2 起点 0.25，以实测校正）
docker exec -d vllm-omni-dev bash -c 'nohup vllm serve /models/Qwen2.5-7B-Instruct \
  --host 0.0.0.0 --port 8000 \
  --gpu-memory-utilization 0.25 --max-model-len 8192 \
  --served-model-name qwen2.5-7b > /tmp/vllm.log 2>&1 &'

# big = 固定 FP8 制品（D4）；双实例时 fast=0.25 + big=0.45（以实测校正）
# docker exec -d vllm-omni-dev bash -c 'nohup vllm serve /models/Qwen3.6-27B-FP8 \
#   --host 0.0.0.0 --port 8001 \
#   --gpu-memory-utilization 0.45 --max-model-len 8192 \
#   --served-model-name qwen3.6-27b-fp8 > /tmp/vllm-big.log 2>&1 &'

# embed（PoC 可选）：容器内 :8002；Compose 用服务 embedding:7999（01 embed 端口 SSOT）
# export LLM_EMBED_ENDPOINT=http://127.0.0.1:8002/v1
```

> 手动 `docker exec` 起 vLLM 仅用于排障；常规起停请用工程内脚本 `scripts/models.sh`（见 §1.4）。

### 1.2 启动 API + 前端（容器内）

```bash
# 推荐：工程脚本（系统 python，FastAPI 托管 frontend/dist，F2 单入口 :8010）
cd /workspace/2026-07/smart-material-system && ./scripts/start_api.sh

# 等价手动方式（OPS_TOKEN / LLM_* 端点等见 scripts/start_api.sh）
export PYTHONPATH=/workspace/2026-07/smart-material-system
export OPS_TOKEN="${OPS_TOKEN:-dev-ops-token-change-me}"
export LLM_FAST_ENDPOINT="${LLM_FAST_ENDPOINT:-http://127.0.0.1:8000/v1}"
export LLM_BIG_ENDPOINT="${LLM_BIG_ENDPOINT:-http://127.0.0.1:8001/v1}"
export LLM_EMBED_ENDPOINT="${LLM_EMBED_ENDPOINT:-http://127.0.0.1:8002/v1}"
export EMBED_FALLBACK_LEXICAL="${EMBED_FALLBACK_LEXICAL:-1}"
nohup uvicorn app.main:app --host 127.0.0.1 --port 8010 > /tmp/uvicorn_8010.log 2>&1 &
```

> API 绑 `127.0.0.1:8010`（单机模式，05 §1.5）；`frontend/dist` 由 FastAPI 同源托管（F2，11 §5.1）；正式 F3 用 Nginx 容器（[11](11-前后端分离与容器化.md)）。**禁止**长期 `python3 -m http.server` 当正式静态服务。

### 1.3 自检（宿主机）

```bash
for i in $(seq 1 36); do
  out=$(curl -s --max-time 3 http://127.0.0.1:8000/v1/models)
  if echo "$out" | grep -q '"id"'; then echo "vLLM:8000 OK"; break; fi
  sleep 10
done
curl -s --max-time 3 http://127.0.0.1:8001/v1/models || echo "vLLM:8001 未启动（可暂 BIG→8000）"
curl -s http://127.0.0.1:8010/api/query/tables && echo " ← API OK"
curl -s -o /dev/null -w "前端 :8010 HTTP %{http_code}\n" http://127.0.0.1:8010/   # F2 同源（F3 则 :8080）
```

容器重启后：`--restart unless-stopped` 只恢复 `sleep infinity`，**须重新跑 §1.1 + §1.2**（或做成容器内 entrypoint/supervisor，实现阶段再加）。

### 1.4 模型按需起停与内存看门（M-2/M-3，2026-08-09）

`scripts/models.sh` 是 vLLM 三端点（big=:8001 27B-FP8 / fast=:8000 7B / embed=:8002 0.6B）的**按需起停入口**（幂等）：

```bash
scripts/models.sh status                          # 各端点健康 + mem_free
scripts/models.sh start big|fast|embed            # 启动指定端点（fast 需 mem_free≥30G、embed≥8G，防 OOM）
scripts/models.sh start all                       # big → embed → fast
scripts/models.sh stop big|fast|embed|all
EMBED_DEVICE=cpu scripts/models.sh start embed    # M-3：embed 迁 CPU（vLLM --device cpu，不占显存）
```

**内存看门**（02 §7.2）：available 低于阈值时按 **embed → fast** 顺序停，**不停 big**（交互主路径），日志落 `data/eval/mem_guard_*.json`：

```bash
scripts/models.sh mem-guard                       # 阈值 GUARD_EMBED_GB=15 / GUARD_FAST_GB=10（env 可覆盖）
```

**常驻看门狗**（`scripts/models_watchdog.py`）：健康检查 + RSS/MemAvailable 告警 + `--heal` 自愈（仅 big）+ `--guard` 内存看门；建议 cron 每 5 分钟：

```bash
*/5 * * * * cd /workspace/2026-07/smart-material-system && \
  python3 scripts/models_watchdog.py --heal --guard >> /tmp/models_watchdog.log 2>&1
```

Stage2 解限重开（GPU fast）见 [02-模型问题反馈.md §六](../../治理方案/question/02-模型问题反馈.md)（权威主库 `治理方案/question/`）。
