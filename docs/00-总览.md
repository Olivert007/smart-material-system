## 1. 总体架构

### 1.1 逻辑分层（SSOT）

| 层 | 职责 | 技术 |
|---|---|---|
| 展示层 | 问答、接入、治理、指标、模型、运维 | Vue3 + Element Plus |
| API 层 | 鉴权边界、参数校验、编排、只读查询 | FastAPI |
| 发布层 | **业务库唯一写入者**、幂等发布、审计 | writer service |
| 任务层 | 解析、画像、规则计算、LLM 调用 | 可恢复 intake-worker |
| 元数据层 | 任务、规则、指标、审计、llm_call | **SQLite WAL**（D1） |
| 分析数据层 | 标准事实表 / 维表、只读分析 | **DuckDB + Parquet** |
| 文件层 | 原始上传、证据、staging、归档、备份 | 宿主机持久化目录 |
| 模型层 | embed 召回 + fast / big 生成；PolicyRouter 编排 | Embedding 小服务 + 独立 vLLM（可分容器） |

### 1.2 目标运行拓扑（Compose 分服务，D3 / D9）

```
本机浏览器（单机模式仅 127.0.0.1）
   │
frontend/nginx:8080  ← 唯一宿主机入口（同源 /api/v1、/events）
   │
   └─ api:8010（内部）── SQLite meta/task（WAL）
              │
       intake-worker ── Parquet evidence/staging
              │
       writer ── DuckDB 业务库（唯一写）
              │
       embed / vllm-fast / vllm-big（仅内部网络）
```

- 防双写靠 **唯一 writer + 业务库只读挂载/只读连接 + 幂等协议**，不靠「所有进程塞进一个容器」。
- 正式态 **不**把 api/vLLM 端口 publish 到宿主机；开发用 Vite `:5173` 代理（[11](11-前后端分离与容器化.md)）。
- 镜像与依赖预导入本机；运行时 **offline**（禁自动拉模型/pip/npm）。
- 模型编排见 [09](09-多模型编排策略.md)；启用门槛见 [10](10-模型评测与验收.md)。

### 1.3 PoC 拓扑（复用现有 `vllm-omni-dev`，非生产终态）

第一阶段可复用单 GPU 容器跑 API+worker+vLLM，但必须：

1. 补进程管理（entrypoint / supervisord），容器重启后可拉起业务进程；
2. meta 用 SQLite、业务写只走 writer（即便同容器也串行）；
3. 端口映射 `8000/8001/8010/8080`，**单机模式绑 127.0.0.1**（D7）；
4. 文档与验收标明：**单容器 = PoC，目标形态仍是 Compose 分服务**。

命令与细节见 [06 §0](06-运维手册.md)。

### 1.4 模型角色称谓（对齐整理3 / 09）

| 角色 | 主选制品 | 说明 |
|---|---|---|
| **embed** | Qwen3-Embedding-0.6B 或 bge-m3 | 候选召回，不直接决策 |
| **fast** | Qwen3.5-9B | Stage 2 起；现有 7B 仅过渡/基线 |
| **big** | Qwen3.6-27B-FP8（固定 revision） | 主生成；禁止模糊 Q8 体积估算（D4） |

- Coder-30B 仅 Stage 4 A/B，不得与 9B+27B 三生成模型长期同驻。
- fast+big 是否长期常驻由评测门槛决定（D8 / [10 §4](10-模型评测与验收.md)）。

## 3. 全局硬约束

| ID | 约束 | 说明 |
|---|---|---|
| C1 | 业务查询只读 | 问答/探索只用 `biz_conn()` 只读；DuckDB 关闭危险扩展能力（05） |
| C2 | 业务写入唯一入口 | 仅 writer service；禁止 API/worker 直接写业务库 |
| C3 | LLM 无执行权 | 产出须白名单/人工确认后才执行 |
| C4 | 冲突不静默选 | 互验/采样/字典多候选/口径冲突 → 人工；互验任一侧不可用 → `unverified`，不得标 consistent（D5） |
| C5 | 确认门不可旁路 | staging → dry-run → 条件 confirm → 幂等 release（03 §4.7） |
| C6 | 配置驱动不生成代码 | LLM 不写可执行代码 |
| C7 | 数据不出本机 + 离线模式 | 挂载卷持久化；禁运行时自动下载 |
| C8 | 写操作可归因 | 单机 ops token；LAN 模式登录角色；`confirmed_by` 来自认证主体 |
| C9 | 任务可恢复 | SQLite 任务表 + worker；禁纯 BackgroundTasks |
| C10 | 模型制品固定 | revision/SHA256/体积/内存实测绑定启动参数（D4） |
| C11 | 拓扑分目标与 PoC | 生产 Compose；单容器 PoC 不得当作终态（D3） |
| C12 | SQL 以 AST 为主防线 | sqlglot 等解析；黑名单/剥注释仅辅助（05） |
| C13 | 前端不直连库与模型 | 只走同源 `/api/v1`；禁止业务代码写死 vLLM/DB 地址（11） |
| C14 | 契约防漂移 | OpenAPI 为 schema SSOT；前端生成类型 + `api:check`（11/05） |

### 3.1 连接与写路径

| 连接 | 存储 | 模式 | 调用方 |
|---|---|---|---|
| `meta_conn()` | **meta.sqlite**（WAL） | 读写 | API / worker（注意事务短） |
| `biz_conn()` | 物资库.duckdb | **只读** | API 查询、问答、dry-run 对照 |
| writer 内部写连接 | 物资库.duckdb | **唯一读写** | 仅 writer：`intake_release` / `master_apply` / `lineage_rebuild` |

合法写路径：

1. staging confirm → writer 幂等发布（`release_id`）  
2. 主数据审批 → writer  
3. 按 release 血缘撤销/重建（D6）→ writer  

每次写入写 `write_audit`（在 SQLite meta）。

### 3.2 冲突与编排（对齐 D5）

| 场景 | 策略 |
|---|---|
| 互验 | 两侧必须真实打到不同端点/模型 ID；**禁止 fallback**；不可用 → `unverified` |
| 级联 | **fast 草稿 → big 审查并出终稿 → 规则/白名单校验**（不再由 fast 重写终稿） |
| 普通生成失败 | 允许 big→fast→规则降级（与互验分离）；详见 [09 §7](09-多模型编排策略.md) |
| 字典多候选 | embed/规则召回 hits 只排序预填；**多候选不可直接进可发布配置**（须人工） |

### 3.3 遗留接口

| 接口 | 定位 |
|---|---|
| `POST /api/ingest` | legacy；默认 403；需 ops + `ALLOW_LEGACY_INGEST=1` |
| 自由 `POST /api/query` | Phase A 起收缩：默认 `ALLOW_FREE_QUERY=0` → 403；仅 ops+显式开关可开（[05 §2.1](05-安全与API规范.md)）；优先指标模板与 `/api/ask` |

## 5. 核心设计决策（摘要）

| 决策 | 理由 |
|---|---|
| SQLite meta + DuckDB 分析（D1） | 避免 DuckDB 多进程写锁；任务队列需要 WAL 并发 |
| 唯一 writer + 幂等 release（D2） | 跨库崩溃可恢复；防重复事实行 |
| Compose 目标 / 单容器 PoC（D3） | 解耦生命周期；PoC 复用现卡 |
| 正式单入口 + 内部网（D9） | 同源免 CORS；缩小暴露面 |
| 互验无 fallback / 级联 big 终稿（D5） | 杜绝「同模型假互验」与弱模型覆盖终稿 |
| PolicyRouter + ConfidenceScorer（09） | 确定性路由；模型自报置信不作执行依据 |
| 血缘重建回滚（D6） | 合并/重关联无可靠通用 reverse |
| 识别抽样、规则全量 | 控 LLM 成本与确定性 |
| 指标模板+固定测试 | 防口径文字与 SQL 不一致 |
