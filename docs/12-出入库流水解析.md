## 1. 问题定义

### 1.1 源头数据现状（审计证据）

出入库记录散落在 **305B 台账** 与 **ZW 物资台账** 的「入库记录 / 出库记录」列，均为**自由文本流**，一个单元格可含多笔、多语义：

| 来源 Sheet | 出入库列 | 非空率 | 样例 |
|---|---|---|---|
| 台账305B_低值易耗 | 入库记录 | 29/39 (74%) | `2023年`、`2024-07-01`、`2022年` |
| 台账305B_低值易耗 | 出库记录 | 19/39 (49%) | `2025.07，张停伟、陈乐言，标签打印`、`2026.4.14出库至溪洛渡1个` |
| 台账305B_维护材料 | 入库记录 | 489/491 (99.6%) | `2024年之前采购`、`2025年9月，张停伟维护材料采购，沈鸿入库`、`…入库4包；2026年6月，…入库6包` |
| 台账305B_维护材料 | 出库记录 | 104/491 (21%) | `2026.1.6/李茜/西坝大楼2408会议室搭建备用使用`、`2025年10月，徐吉领用3个，用于机房音频配线` |
| 台账305B_备品备件 | 入库记录 | 221/223 (99%) | `2022-08-17 00:00:00`、`2025-09-01`（纯日期，无经手人） |
| 台账305B_备品备件 | 出库记录 | 5/223 (2%) | `2024.12.30 借用给宜昌分部`、`2026年6月15日…安装使用（新增槽位） 序列号：…`、`已使用` |
| ZW物资_成都区域ZW物资台账 | 出库记录（ZW） | 264/910 (29%) | `2026.1.6/李茜/西坝大楼2408会议室搭建备用使用` |
| ZW物资_成都区域ZW物资台账 | 入库记录 | 0/910 (0%) | —（该表无入库文本） |

问题归纳：

1. **格式不统一**：同一列混用 `yyyy-MM-dd`、`yyyy.M.d`、`yyyy年M月`、`yyyy.MM.dd 说明`、纯文本「已使用」、纯文本「2024年之前采购」。
2. **多笔合并在一个单元格**：以 `；` / `;` / `。` / 换行分隔多笔，须**拆分**为多条流水。
3. **字段错位/缺失**：经手人、用途、数量位置不固定；部分只有日期；部分「已使用」无日期数量。
4. **数量与文本分离**：数量常另有「入库数量/出库数量」列，文本内又有「4包」「1个」，需交叉校验（§4.5）。
5. **现有解析错误**：当前流水把文本首段年份当数量（如日期串 → `quantity=2025.0`），`person`/`purpose` 全空，行数远低于可解析量。

## 2. 目标：`fact_stock_flow` 结构化表（SSOT）

物理表 `fact_stock_flow`（DuckDB），与现有 6 表并列，**仅由 writer 写入**（00 D2 / FL3）。

| 列 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `flow_id` | VARCHAR | PK | 全局唯一，`FL{seq}`，writer 幂等生成 |
| `material_id` | VARCHAR | 是 | 关联 `dim_material.material_id` |
| `flow_type` | VARCHAR | 是 | `IN` / `OUT`（枚举；借用暂归 OUT，见 §2.1） |
| `flow_date` | DATE | 条件 | 业务日期；解析失败 → NULL，且不得标 L1 |
| `quantity` | DOUBLE | 条件 | 拆数量；解析不出 → NULL；L1 必须非空 |
| `unit` | VARCHAR | 否 | 计量单位（文本或列单位） |
| `person` | VARCHAR | 否 | 经手人/领用人；多人用 `;` 连接（§4.3） |
| `purpose` | VARCHAR | 否 | 用途/原因（去日期/数量/人名后的剩余） |
| `remark` | VARCHAR | 否 | **原始文本全文**（审计可还原）；可附校验提示 |
| `parse_level` | VARCHAR | 是 | `L1` / `L2` / `L3`（§4.4） |
| `parse_source` | VARCHAR | 是 | `rule` / `llm` / `example` / `manual` |
| `source_file` | VARCHAR | 是 | 来源文件名 |
| `source_sheet` | VARCHAR | 是 | 来源 Sheet |
| `source_row` | BIGINT | 是 | 来源 Excel 行号 |
| `source_segment` | INT | 是 | 同单元格内第几笔（从 0）；未拆默认 0 |
| `release_id` | VARCHAR | 是 | 幂等发布批次（03 §4.7） |

约束：

- 一行源头文本 → **0..N** 条流水；拆不出则**不丢弃原文**——进待确认清单，`remark` 保留全文。
- L3：**不生成**业务流水行（或仅生成占位审计行由实现二选一，默认**不生成**），原文进 `flow_pending`。
- 勾稽不通过 → 标记并入差异清单，**不阻止**同批次其他合格流水发布（FL6）。

### 2.1 借用 / 内部流转（PoC 边界）

| 语义 | PoC（FL4） | 若客户后续要求「借出不减库存」 |
|---|---|---|
| 借用、借出、内部流转 | `flow_type=OUT`，`remark` 含原文 + 可选标签 `[BORROW]` | 扩展枚举 `BORROW` / `RETURN`，勾稽公式改写，指标字典 version+1 |

未接到明确库存口径前，**不**提前实现 BORROW 枚举，避免口径分叉。

## 3. 解析总体策略（对齐 03 配置驱动）

```
入库记录 / 出库记录 文本列（证据层 raw_value）
  │
  ▼
【A · 规则路径 · 挂 03 Step5】确定性，不耗 LLM
  split_flow_text → extract_flow_fields → 交叉校验(§4.5) → L1/L2/L3
  │  L1：可随 staging 进入可发布候选
  │  L2/L3 或规则未覆盖：写入 flow_pending（meta）
  ▼
【B · LLM 兜底 · 独立任务，非 Step5】Phase B+
  仅消费 flow_pending 中规则失败/低置信样本
  fast 出结构化 JSON；低置信 escalate big
  产出 → 仍进 flow_pending，须人工确认（C3），不得直写业务库
  ▼
【C · 人工确认 · 治理中心】
  接受 / 修正 / 忽略 → 回写 flow_example（§5）→ 触发最小重跑集合（03 §3.2）
```

原则：

- **识别用样本，规则算全量**：规则对全量文本跑（DuckDB/向量化，秒级）；LLM 只处理 pending。
- **配置驱动**：每个「来源 Sheet × 出入库列」一套 `flow_config`，落 meta.sqlite，确认后复用（同 03 §1.1）。
- **与接入流水线关系**：
  - Step2 映射可将列标为 `std_field=flow_in_text` / `flow_out_text`（或 `clean=flow_text` + 方向由列名/配置给出）。
  - Step5 **只执行** `split_flow_text` / `extract_flow_fields` 及交叉校验（FL2）。
  - LLM 兜底任务由 worker 调度，状态进 SQLite（C9），与画像/建议同类。

### 3.1 `flow_config`（示意）

```json
{
  "source_sheet": "台账305B_维护材料",
  "flow_columns": [
    {
      "header": "入库记录",
      "flow_type": "IN",
      "qty_column": "入库数量",
      "unit_column": "单位",
      "separators": ["；", ";", "。", "\n"],
      "date_formats": ["yyyy-MM-dd", "yyyy.M.d", "yyyy年M月", "yyyy/M/d"],
      "qty_patterns": ["入?库?(\\d+(?:\\.\\d+)?)(个|台|包|根|对|条|部|套|把|米|卷)?"],
      "person_delims": ["、", ",", "，", "/"]
    }
  ]
}
```

经人工确认后写入 `intake_report` / 独立 `flow_config` 表；变更走 04 §6.7 dry-run。

## 4. 解析原语（03 清洗动作库新增）

### 4.1 `split_flow_text(text, sep_dict) -> [segment]`

按分隔符集合拆多笔；启发式：分隔符后紧跟日期/年份关键词（如 `2026年`、`2025.`）且前一段已完整时，强制切分。

示例：`2025年6月，张停伟…入库4包；2026年6月，…入库6包`  
→ `[2025年6月…入库4包, 2026年6月…入库6包]`

### 4.2 `extract_flow_fields(segment, date_formats, pos_dict) -> fields`

- **日期**：复用/扩展 `clean_date`；覆盖 305B ≥5 种格式。
- **数量/单位**：优先文本内「入/出库?N单位」「领用N个」；否则见 §4.5。
- **经手人**：位置词典 + 分隔符；见 §4.3。
- **用途**：去掉日期/数量/人名后的剩余文本。
- **特例**：
  - `2024年之前采购` / 仅 `2023年` → `flow_date=NULL`（或仅年到年的约定需人工定），`parse_level=L2`。
  - `已使用` / `无` / 空 → `L3`，仅保留原文进 pending。

### 4.3 多人 / 多对象

- 多人（`张停伟、陈乐言`）：`person = "张停伟;陈乐言"`，**不**拆成多条流水（同一笔业务）。
- 同单元格多笔：由 §4.1 拆段后每段一行（`source_segment` 递增）。

### 4.4 置信分级

| 级别 | 判据 | 动作 |
|---|---|---|
| `L1` | 规则（或已确认示例）全拆；**日期 + 数量齐全**且过 §4.5 | 可进 staging 发布候选 |
| `L2` | 部分字段缺失（有日期无人/无数量但可借单列等） | 可发布**或**仅进 pending（默认：**入库 + 进待确认补录**）；须在 UI 可见 |
| `L3` | 无法结构化 | **不生成**流水行；pending 人工补录或确认「无业务流水」 |

`parse_source`：`rule`（Step5）/ `example`（命中 `flow_example`）/ `llm`（兜底建议）/ `manual`（人工录入）。

### 4.5 数量交叉校验（优先级，FL5）

按段判定，**禁止**将四位年份、日期串中的数字当作 `quantity`：

| 优先级 | 条件 | `quantity` 来源 |
|---|---|---|
| P1 | 文本段内匹配到明确数量模式 | 用文本数量；若与单列总量不一致 → 以文本为准（多笔场景），`remark` 记 `qty_mismatch:col=…` |
| P2 | 文本**无**数量，且本单元格只拆出 **1** 段 | 用同列「入库数量/出库数量」 |
| P3 | 文本无数量，且拆出 **多** 段 | 各段 `quantity=NULL`，整组 `L2`，进 pending（不可臆造均分） |
| P4 | 纯日期单元格（无业务数量语义） | 用单列数量（P2）；日期只进 `flow_date` |
| P5 | 无法得到数量 | `quantity=NULL`；不得标 L1 |

## 6. 勾稽校验

目标关系（与源头列名公式一致）：

```
对每个 material_id（或约定编码维度）：
  Σ(IN.quantity) − Σ(OUT.quantity)  ≟  fact_inventory.stock_qty − 初始库存
```

- **初始库存**：落 `fact_inventory.opening_qty`；**缺失/NULL 按 0**（PoC 无独立期初台账时等价于「流水净额 ≟ 现有库存」）。有期初来源后写入该列即可，无需改公式。
- **PoC 期初种子**（ops）：`POST /govern/flow/opening/seed` — 仅对「有库存、该 `material_id` 无任何 `fact_stock_flow`」的行写 `opening_qty = stock_qty`（盘点即期初）。**禁止**对已有流水的物资自动轧平；`flow_only` / `mismatch` 差异需主数据对齐或真实期初台账。
- **物资编码对齐**（ops）：`/govern/material/align/*` — 对 flow_only 物资按 03 三层匹配思路提案（L1 编码 / L2 名称±规格；歧义不静默选，C4）。`accept` 经 writer 把 `fact_stock_flow.material_id` 改到库存侧编码；接入时 `build_stock_flow_bundle` 会吃已接受映射与唯一 L2 命中。未匹配的流水物资允许继续以合成 `M-…` 存在（FL6）。
- 勾稽 API 返回 `gap_class`（`inv_only` / `flow_only` / `mismatch`）、`by_class`、`material_id_overlap`，便于区分「无流水覆盖」与「编码对不上」。
- 发布后由 writer 或只读任务跑全量 SQL；差异绝对值 > 阈值（默认 `0.01`）→ **勾稽差异清单**。
- 已知源头出库缺失率高（维护材料约 79%、备品备件约 98%）→ **允许差异存在**，但必须可见、可导出、可补录（FL6）。
- 补录确认后按 03 §3.2 最小重跑集合重算流水与勾稽。
- API `GET/POST /govern/flow/reconcile` 返回 `formula` / `opening_mode` / `opening_populated_rows` 供验收与 UI 标注。

产品话术：差异看板 + 补录，**不**宣称「账已轧平」。

## 8. 指标与质量门禁（对齐 08）

`FLOW_QTY_TOTAL`（及后续出库类指标）在字典中可先 `draft`，**同时满足**方可 `active`：

1. 本模块对目标来源 Sheet 的出入库列已跑通 §3A 规则路径；
2. `L1` 占比与 `L2/L3` pending 量可统计并有基线；
3. §6 勾稽任务可跑通，差异清单可导出（不要求差异为零）；
4. 08 规定的固定测试夹具通过；
5. 错误历史 parquet 已按 FL7 **血缘重建**替换，抽检无「年份当 quantity」。

建议配套只读指标（可选，draft）：

| 指标 | 口径要点 |
|---|---|
| `FLOW_PARSE_L1_RATIO` | L1 行数 /（L1+L2 已发布流水行） |
