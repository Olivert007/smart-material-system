## 根因总述

1. **config 模块 import 时读 env 并绑定常量**（[config.py](file:///workspace/2026-07/smart-material-system/app/config.py) 顶层 `os.environ.get(...)`）：测试文件虽在 `from app import config` 之前设置 `os.environ[...]`，但**全量运行时 config 已被更早收集的测试模块导入**，后续模块的 env 设置全部无效 → 断言基于默认值失败。单独运行（模块自设 env 后 import）可过。
2. **DATA_DIR 全局共享**：多个测试模块各自 `mkdtemp` 并设 `DATA_DIR`，但 config 路径常量只绑定首次导入值 → 全量运行时所有模块共用同一个目录，`file_batch`/`intake_task` 残留造成主键冲突与任务状态串扰。
3. **gate 行为变更未同步进测试**：`confirm_release` 现已先过 staging 质量/计划 gate（`GATE_BLOCKED:NO_COLUMNS`），测试仍期望旧语义 `FileNotFoundError`。

## 逐条问题拆解

| # | 用例 | 现象 | 根因 |
|---|---|---|---|
| Q-1 | `test_p1_limits_retry_backup.py::test_llm_retries` | `AssertionError: slow`，`calls["n"] != 3` | 文件顶部设 `LLM_MAX_RETRIES=2` 但未生效（config 已导入，取默认 1）→ 只重试 1 次；`assert res.ok` 失败 |
| Q-2 | `test_p1_limits_retry_backup.py::test_upload_limits` | `AssertionError: expected MAX_FILES` | 同因：`UPLOAD_MAX_FILES=2` / `UPLOAD_MAX_BATCH_BYTES=1000` / `UPLOAD_DIR_QUOTA_BYTES=500` 全部未生效（用默认 50/4GB/200GB）→ 限额断言不触发 |
| Q-3 | `test_heartbeat_recovery.py::test_recover_only_stale` | `recover_orphan_tasks()` 返回数 ≠ 2 | `TASK_HEARTBEAT_TIMEOUT_SEC=60` 未生效（取默认值）→ 600s 的 `t_stale` 未被判定 stale → 未恢复为 pending |
| Q-4 | `test_heartbeat_recovery.py::test_max_attempts_fails` | `sqlite3.IntegrityError` | `TASK_MAX_ATTEMPTS=3` 未生效（默认 5）→ attempt=3 不标 failed；且 DATA_DIR 共享使 `file_batch` 残留（`_ins` 复用 task_id 作 file_id 撞主键） |
| Q-5 | `test_intake_analyze.py::test_analyze_then_release` | 任务/断言失败 | DATA_DIR 共享：worker 轮询与其它用例残留的 file_batch/intake_task 相互干扰（该文件独立运行时通过） |
| Q-6 | `test_confirm_staging_snapshot.py::test_confirm_picks_staging_id` | **单独运行也失败** | `confirm_release` 先抛 `RuntimeError: GATE_BLOCKED:NO_COLUMNS`（staging 无 payload 列），测试仍期望 `FileNotFoundError`；CAS 后状态断言也不匹配 |

---

## 修复方案（建议顺序）

1. **conftest.py 统一固化 env**（根治 Q-1~Q-4）：
   - 在 `conftest.py` 收集期（测试模块 import 之前）设置全部测试用 env：`DATA_DIR`、`OPS_TOKEN`、`LLM_MAX_RETRIES`、`TASK_HEARTBEAT_TIMEOUT_SEC`、`TASK_MAX_ATTEMPTS`、`UPLOAD_*` 等；
   - 或更稳妥：`config.py` 提供运行时重设入口（如 `configure(**overrides)` / 测试内 `monkeypatch.setattr(config, "LLM_MAX_RETRIES", 2)` 后调用依赖该常量的函数），避免依赖"先设 env 再 import"的脆弱顺序。
2. **DATA_DIR 按模块隔离**（根治 Q-5，辅助 Q-4）：
   - conftest 提供 autouse fixture，每个测试模块用独立 tmp 目录并 `monkeypatch` 覆盖 `config.DATA`/`UPLOAD`/`RAW`/`STAGING`/`META_DB` 等路径常量；
   - 或保留"模块级 tmp + 先于 import 设 env"，但要求 conftest 保证每次 `pytest` 进程只被一个 DATA_DIR 绑定（即全量运行下仍不可行）→ 必须走运行时重设路线。
3. **同步 gate 语义进测试**（根治 Q-6）：
   - `test_confirm_picks_staging_id` 改为先构造带 payload 的 staging（parquet 落盘）再 confirm；或按新语义断言 `GATE_BLOCKED:NO_COLUMNS`，并同步 CAS 后状态断言。
4. **回归标准**：`pytest tests/` 全量 40 用例 **0 失败**；且 `test_p1_limits_retry_backup.py`、`test_heartbeat_recovery.py`、`test_intake_analyze.py` 各自单文件运行仍可通过（不因隔离方案而互斥）。
