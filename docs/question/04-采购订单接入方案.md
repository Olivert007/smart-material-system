## 一、定位

采购订单作为**新业务域 `purchase_order`（第 7 个域）**复用现有可信管线，不旁路：

```
上传 → evidence → tabular → staging(映射) → confirm → writer 幂等发布 → fact_purchase_order
```

与现有域（inventory/asset/demand/quota/stock_flow/material）并列，走 03 配置驱动标准路径。改动集中在 4 层：数据模型、映射、勾稽、指标。

> ⚠️ 写入路径注（2026-08-09）：`writer.DOMAIN_FACT_TABLE` 现仅含 **inventory/demand/asset/stock_flow 4 个发布域**；quota 域走 `intake_plan._TARGET_TABLE`。PO 落地时需确认走 `DOMAIN_FACT_TABLE` 通用分支（推荐，与 4 域同构）还是仿 quota 的 `_TARGET_TABLE` 路径。

## 二、数据模型层（schema.py）

新增事实表 `fact_purchase_order`，**一行一订单行**：

```sql
CREATE TABLE fact_purchase_order (
    po_id         VARCHAR PRIMARY KEY,   -- PO-{release_id}-{seq}
    po_no         VARCHAR,               -- 采购单号（可能为空，用材料+日期兜底）
    material_id   VARCHAR,               -- 关联 dim_material
    supplier      VARCHAR,               -- 供应商
    order_date    VARCHAR,               -- 下单日期
    due_date      VARCHAR,               -- 要求到货/交期
    quantity      DOUBLE,                -- 订购数量
    received_qty  DOUBLE,                -- 累计已到货数量
    unit          VARCHAR,
    unit_price    DOUBLE,                -- 单价（含税/不含税口径需定）
    total_price   DOUBLE,                -- 金额
    buyer         VARCHAR,               -- 采购员
    status        VARCHAR,               -- open/partial/received/closed
    source_file   VARCHAR,
    source_release_id VARCHAR
)
```

**关键打通点**：`fact_stock_flow` 目前无 PO 关联字段。若做"采购→入库"**单据级**精确对账，需给 `fact_stock_flow` 加可空列 `po_id`（映射/解析时从来源列或文本带出）；否则只能做物料级汇总对账（ΣIN vs Σreceived by material_id），无法逐单核销。

## 三、映射层（mapping.py / embed_recall.py / flow_config.py）

1. `mapping.ALIASES` 新增 `purchase_order` 域：`po_no`/`supplier`/`order_date`/`due_date`/`quantity`/`unit_price`/`total_price`/`buyer`/`status` 中文别名（参照现有域写法）。
2. `ALLOWED_STD`（embed_recall）同步加 `po_*` 标准字段 → 治理中心表头映射页可生成建议、人工确认回写 rule_dict。
3. 可复用 2026-08-09 已落地的**配置驱动**机制（`app/services/flow_config.py`，docs/12 A3）：PO 结构化列映射走 `data/flow_config/*.json`（header/qty/unit 覆盖）+ aliases 自动注册，避免硬编码映射分支。
4. 源头限制：若采购单为**自由文本列**（类似 305B 出入库），需扩展模块 12 原语（po 文本拆解）；否则只支持结构化列接入。

## 四、勾稽口径扩展（flow_gov.py）

现有勾稽仅 `ΣIN−ΣOUT vs stock_qty`（FL6）。接入后新增两条到货口径：

| 勾稽 | 公式 | 精度 |
|---|---|---|
| 到货勾稽（物料级） | Σ IN(入库流水) vs Σ po.received_qty（按 material_id） | 汇总级 |
| 到货勾稽（订单级） | Σ IN(po_id) vs po.received_qty（需 flow 带 po_id 列） | 单据级 ✅ 推荐 |
| 库存勾稽 | 现有公式不变 | — |

差异照 FL6 处理：可见、可导出、可补录、不阻塞发布；落 `po_reconcile_gap` 或并入现有差异清单（需定）。

## 五、指标层（metrics.py）

复用 `metric_dict + evaluate_metric`，新增业务指标。**不设 FLOW_* 式门禁**，可直接 active：

| 指标 | 口径 |
|---|---|
| `PO_OPEN_QTY` 在途量 | Σ(quantity − received_qty) |
| `PO_RECEIVE_RATE` 到货率 | Σreceived / Σquantity |
| `PO_TOTAL_AMOUNT` 采购总额 | Σ(quantity × unit_price) 或 Σtotal_price（口径随含税决策） |

## 六、人员与单据边界

- 采购员 `buyer` 落 PO 表，与流水 `person`（经手人）、库存 `custodian`（保管人）、资产 `user_name/manager`、需求 `reporter` 并列——仍是**业务字段，非维度表**（与现有设计一致）。
- 采购订单是**单据实体**（有状态流转 open→closed），与流水（事件流）性质不同 → 单独成表，不并入 flow。

## 七、可复用的新增能力（2026-08-09 P1–P4 已落地）

采购域接入时，治理管线新组件可直接套用，无需从零开发：

| 组件 | PO 场景用途 |
|---|---|
| `value_rule` + staging 接入 | 采购单校验规则：`unit_price>0`、`supplier` 非空、`quantity>0`、`po_no` 唯一等（种子规则 + `/govern/value-rules` 管理） |
| `staging_blocked` 逐行明细 | 采购单坏行不整批回滚，落 `staging_blocked` 可改可重试 |
| `rule_learn` 提案 | PO 表头别名学习：`rule_learn/propose` → `govern_confirm` → 回写，无需人工全量维护 |
| `release diff / supersede` | 采购单修订走"新 release + supersede"，禁原地 UPDATE，与 correction 通道一致 |
| `report_definition/report_run` | 采购报表快照（在途采购、到货率、按供应商/月份聚合）直接建报表定义 |
| `metric_snapshot` + `business_snapshot` | PO 指标（PO_OPEN_QTY 等）时序 + 首页采购卡片 |

## 八、落地顺序

1. **文档先行**：锁定 PO-1~PO-5（单据级对账与否、含税口径、状态枚举、是否解析文本单、差异清单落点）；
2. schema（新表 + flow.po_id）+ 映射（flow_config JSON + ALIASES + ALLOWED_STD）+ writer `DOMAIN_FACT_TABLE` 加 `fact_purchase_order` 分支；
3. 校验与拦截（value_rule + staging_blocked）、勾稽（po_reconcile）与指标（PO_*）；
4. 报表与展示（report_definition 采购报表 / 治理中心"采购订单"页签 / 首页快照）。

## 九、待定决策（PO-1~PO-5）与推荐

| ID | 决策点 | 候选 | **推荐** | 理由 |
|---|---|---|---|---|
| PO-1 | 是否做订单级对账（flow 加 po_id） | 是 / 否 | **是** | 可逐单核销；列可空，旧流水不受影响 |
| PO-2 | 单价含税口径 | 含税 / 不含税 / 双字段 | **含税单字段 + 文档注明** | 与现有台账「合价」习惯一致；双字段增加映射负担 |
| PO-3 | status 枚举 | open/partial/received/closed / 按客户实际 | **四态枚举** | 覆盖在途/到货场景；接入时 `value_rule` 校验 |

1. 上传采购单 → staging → confirm → `fact_purchase_order` 有行、幂等可重放；
2. 若 PO-1=是：入库流水带 `po_id` 时，订单级到货勾稽可查；
3. `PO_OPEN_QTY` / `PO_RECEIVE_RATE` 指标可 evaluate；
4. 全程无 `UPDATE fact_purchase_order` 原地修改。
