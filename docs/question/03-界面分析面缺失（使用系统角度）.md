## 一、原观察（第 1 版，2026-08-09 03:58 时点）

逐页盘点用户能看到的内容：

| 页面 | 展示内容 | 性质 |
|---|---|---|
| 首页 HomeView | 表行数卡片、流水 L1/L2/L3、gate 门禁、FLOW_* 指标值、模型状态、最近文件 | 计数/状态，无业务分析 |
| 治理中心 GovernView | 表头映射、流水解析级别、勾稽差异清单 | 规则/质量异常导向 |
| 指标字典 MetricsView | metric 定义、draft/active 状态、version、门禁激活 | 规则治理，无趋势/对比 |
| 自学习资产 AssetsView | rule_dict / flow_example / 确认历史 / few-shot | 全部是规则资产 |
| 问答 AskView | Text2SQL 裸表格结果 | 唯一分析入口，但无图表 |
| 运维 OpsView / 模型 ModelsView / 设置 SettingsView | 运维状态 | 运维工具 |

> 第 1 版结论：页面以"规则字段"为主，业务数据只见 `COUNT(*)` 行数（`stats_overview._table_counts`），分析入口被安全/模型约束限死。

## 二.5、指标口径/字段 用户视角评审（2026-08-09 第 3 版新增）

## 三、根因（仍有效）

1. **产品定位**：治理/可信管道优先，分析为后加层。
2. **能力分层**：后端已有 `metric_snapshot`、`seed_reports` 按月趋势 SQL，但 **HomeView/GovernView 未接线**（非从零开发）。
3. **指标口径**：U-1~U-6 使用户对已展示数字失去信任（跨单位求和、恒 0 指标）。

## 四、剩余建议与解决方案（按投入产出比）

### UI-1 · 治理中心「流水分析」tab（P2）

| 项 | 方案 |
|---|---|
| 数据 | 复用 `seed_reports` 中出入库按月 SQL，或新增 `GET /api/v1/analytics/flow-monthly`（AST 只读） |
| 展示 | GovernView 新 tab：IN/OUT 折线、Top 物资柱状、L2/L3 占比饼图 |
| 验收 | 与 ReportsView 同口径数字一致 |

### UI-2 · 首页迷你趋势（P2）

| 项 | 方案 |
|---|---|
| 数据 | `metric_snapshot` 近 6 点 或 报表 API 最近 6 月 |
| 展示 | HomeView 业务快照区下方 1 行 sparkline |
| 验收 | 不增加首屏 >500ms（可懒加载） |

### UI-3 · MetricsView 业务指标时序（P2）

| 项 | 方案 |
|---|---|
| 数据 | 已有 `/metrics/{id}/snapshots` |
| 改动 | worker 对 `metric_group=business` 开定时 `evaluate_metric(..., write_snapshot=True)` |
| 展示 | MetricsView 详情页 ECharts 折线 |

### UI-4 · 报表参数化（✅ 已落地 2026-08-09）

`ReportsView` 按 `params_json` 渲染动态表单（`{name,label,type}` 声明）→ 触发 `run_report(params)`；后端 `report_runner._render_params` 将 SQL 中 `${name}` 白名单替换（字符串引号包裹、数字直替），渲染后二次过 AST 只读校验；缺参/非法值报 `REPORT_FAILED`。种子示例：`rpt_inv_filtered`（类别 + 最低库存）。

### UI-5 · ReportsView 入主路径（P2，低成本）

HomeView 增加「定期报表」卡片，链到 ReportsView 预置 4 条种子报表（含按月趋势）。

### 原 §四 第 4 项 · 自学习成效（P3）

| 项 | 方案 |
|---|---|
| 指标 | rule_learn 确认率、few-shot 命中次数（需新增审计聚合 SQL） |
| 展示 | AssetsView 顶部摘要卡或 GovernView 子 tab |
