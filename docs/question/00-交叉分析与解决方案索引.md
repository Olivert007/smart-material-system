## 2. 五条根因

### R1 · Schema 薄（数据层）

台账源文件有列，系统 `fact_*` 未落库或未映射 → `business_snapshot` 与多个指标恒 0/恒空。

- **表现**：U-2/U-3/U-5、G-1、中危 1
- **枢纽**：[ledger-export-plan.md](../../roadmap/ledger-export-plan.md) T1–T7
- **与 04 联动**：`supplier` 等字段与 PO 域共用「可空列 + 新 release 写入」路径，避免两套迁移

### R2 · 指标未分层（展示层）

14 项 active 混排：业务 9 + 运维 2（INTAKE_*）+ 质量门 3（FLOW_*）；另 FLOW_QTY_TOTAL 与业务 FLOW_IN_QTY_TOTAL 口径重复（U-4）。

- **表现**：U-1、U-4；FLOW_* 已 active（gate 需要）但不应出现在业务卡片区
- **原则**：**不删除** FLOW_QTY_TOTAL（破坏 gate checklist），改 `group` + 别名 + 首页过滤

### R3 · 治理优先架构（产品层）

页面先服务接入/治理；分析能力后端就绪（`metric_snapshot`、`seed_reports`）但主界面未暴露。

- **表现**：03 UI-1~3；06 中「报表已有按月趋势」与「首页无趋势」并存
- **原则**：复用现有 SQL/端点，补 GovernView/HomeView 展示，不新开旁路

### R4 · DGX 统一内存（基础设施）

bf16 三模型常驻 OOM → FP8 + fast CPU 降级 → Stage2 不能 claim。

- **表现**：02 全文、01 中危 3、待处理 #2
- **判定**：当前 gate（CPU fast）仅作稳定性烟雾测试，**不算** docs/09 要求的 GPU 双常驻 claim
- **实测（2026-08-10）**：沙箱内 `nvidia-smi` 可见 GB10，但 `torch.cuda.is_available()=False`（`Error 304: OS call failed`）——CUDA 计算被沙箱禁用，vLLM GPU 启动必然失败（本轮已实测 `models.sh start all` 三端点均 Engine 启动失败后清理）。**Stage2 claim 保持未达成，等外部环境解限后重开**。

### R5 · 多 sheet 路由不全（接入层）

`evidence.py` 丢弃无流水列 sheet → 公用工器具 94 行、应急备汛 10 行进不来。

- **表现**：G-2；与中危 2（对齐 gap 324）叠加降低用户信任
