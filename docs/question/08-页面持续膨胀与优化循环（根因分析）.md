# 页面持续膨胀与优化循环（根因分析）

> 版本：v0.1（2026-08-10）· 状态：待评审
> 视角：**信息架构（IA）与优化流程**——导航 / 路由 / 页面 / roadmap 方案为何"一直在增加"
> 范围：`frontend/src/App.vue`、`frontend/src/router/index.ts`、`frontend/src/pages/*.vue`、`roadmap/*.md` 及本文档集各 review 方案

## 0. 结论摘要

系统页面数量与"页面优化"工作量一直在增加，不是单一原因，而是**信息架构缺失 + 优化流程自增长**共同作用，可归纳为 6 条：

1. **导航 / 路由 / 页面三者不对齐**：导航 15 项 > 路由 13 项 = 页面 13 个；`/lineage`、`/audit` 两个"未实现路由"已先挂在导航上。
2. **页面按后端功能模块镜像，而非按用户受众/任务规划**：`HomeView` 408 行、10 个区块、10 个跳转按钮，是"入口聚合器"而非"业务一眼"。
3. **优化方案的"新增"多于"删除"**：补任务队列/告警/成本卡、新增 `/audit`、`/lineage` 页；而"收敛/删除"类任务大多挂在未决决策点（ED）上迟迟不执行，净页面数不降反升。
4. **review 文档互相引用、层层追加**：12 篇 roadmap 方案，9 篇为 2026-08-10 同日产出，形成"方案依赖链"，文档数量自身滚雪球。
5. **同一问题被多个方案重复发现、重复规划**：模型卡中文化在 HG-1.3 / MB-3.3 / AO-2.5 三处重复，L1/L2/L3 释义在 MB-3.2 / AO-2.6 重复。
6. **缺一份统一的"术语规范 + 页面职责清单"基线**，导致每页 review 都重新踩同一个坑。

**结论**：按本文 §3 止血（导航=路由=页面三对齐 → 定页面职责清单 → 先收敛后新增），页面膨胀可停止；不涉及任何后端能力变更，与既有可信流水线 / 口径克制不冲突。

## 2. 根因分析

### 2.1 直接原因

| # | 原因 | 证据 |
|---|---|---|
| D1 | **方案先行、页面后补**：新页还没实现，导航/文档先挂上 | `/lineage`、`/audit` 已进 [App.vue](file:///workspace/2026-07/smart-material-system/frontend/src/App.vue#L23-L24) 菜单，路由未建 |

### 2.2 深层原因

| # | 原因 | 说明 |
|---|---|---|
| R-A | **页面按"后端功能模块"镜像，而非按"用户受众/任务"规划** | 后端 30+ service（flow_\*、rule_\*、mapping、text2sql…）每加一个能力，前端就加一个页面/区块。assets-ops 文档自述根因："两页是后端表/JSON 的前台镜像，不是'用户问题的解答'" |
| R-B | **缺信息架构（IA）基线** | 未先定"受众分层（业务/接入/治理/Ops）× 每受众入口数"框架；新增功能无处安放就塞总览/塞导航 |
| R-C | **review 循环 + 方案依赖链** | 每个 review 方案发现新问题 → 生成新任务与新 ED → 被后续方案引用；12 篇 roadmap、9 篇同日产出即为此循环的产物 |
| R-D | **同一问题被重复规划** | 见 §2.3 重复清单：缺统一"术语规范 + 页面职责清单"，每页 review 都重新发现同样的坑 |

## 3. 止血建议（按优先级）

| 顺序 | 措施 | 落点 | 说明 |
|---|---|---|---|
| 1 | **导航 = 路由 = 页面 三对齐** | [App.vue](file:///workspace/2026-07/smart-material-system/frontend/src/App.vue#L6-L26) | 摘除（或置灰）未实现的 `/lineage`、`/audit`；此后新增导航项必须先有路由与页面 |
| 2 | **定页面职责清单（IA 基线）** | 本文档 §5 决策后落一份清单文档 | 按受众分区固定每区页面数上限（如 看数 ≤4 / 治理 ≤3 / 平台 ≤5）；新增页面必须同时删一个或合并进现有页 |
| 3 | **先收敛、后新增** | 见 §3.1 收敛任务清单 | 收敛项落地后，再按决策点决定是否需要新页面 |
| 4 | **重复规划合并执行** | 模型卡 / L1/L2/L3 文案 | 以一处为准，其余方案引用同一任务 ID |
| 5 | **删除类任务去 ED 依赖** | 各方案 ED 表 | 对"收敛"类 ED 尽快拍板（默认采纳推荐项），避免收敛永远挂起 |

## 6. 验收总标准

1. 导航菜单项数 = 路由数 = 页面数（无未实现路由挂在导航）；
2. 总览页区块收敛到"业务一眼 + 数据量 + 门禁 + 入口"，无与 `/metrics` `/models` 重叠的试跑/详情区块；
3. 治理页"流水分析"只读 Tab 迁出或明确标注"只读分析"，Tab 数与职责清单一致；
4. 运维页血缘审计高级操作不挤占健康仪表盘首屏；
5. 模型卡中文化、L1/L2/L3 释义等文案在多个方案中不再重复规划（统一任务 ID 引用）；
6. 收敛类任务不再因 ED 未决而长期挂起；既有可信流水线（写操作三件套、Ops Token、口径克制）不受影响。
