---

## 1. 原则

- 评测以**业务正确性**为主，吞吐/tokens/s 为辅。  
- SQL 看**执行正确率**（相对金标或人工裁定结果），不只语法合法。  
- 双模型、互验、Coder 替换均须过本模块门槛，否则保持单 big + 规则。  
- 故障注入（超时、非法 JSON、端点不可用）与功能集同等重要。

---

## 2. 业务评测集（最低规模）

| 类型 | 最低规模 | 用途 |
|---|---|---|
| 简单单表查询 | 50 | Stage 1 基线 |
| 多表 / 时间 / 排名 / 占比 | 50 | big / Coder A/B |
| 指标口径歧义问题 | 20 | 08 模板与拦截 |
| 多级表头、区域堆叠、异常格式文件 | 20 个文件 | 03 接入 |
| 常规文件表头/角色识别 | 30 个文件 | 映射/画像 |
| 主数据候选匹配 | 100 组 | embed + 规则 |
| 模型不可用 / 超时 / 非法 JSON | 每类 ≥10 | 状态机与降级 |

存放建议：`data/eval/`（金标 SQL/映射 JSON、文件样本清单、SHA256）。离线交付包必须包含（06 §10）。

---

## 3. 核心指标

| 指标 | 定义要点 |
|---|---|
| SQL 执行正确率 | 结果集与金标一致（或业务容差内） |
| 指标口径正确率 | 命中指标且 SQL/模板符合 definition 测试 |
| 表头映射 P/R | 字段级 precision / recall |
| 角色与区域识别准确率 | sheet role / region 边界 |
| 人工介入率 / 修正率 | 进治理中心比例；修正后回写比例 |
| 延迟 | 业务任务 p50 / p95（含校验，不含人工等待） |
| 峰值统一内存 | 六态（09 §10） |
| 降级 / 冲突 / 伪高置信次数 | 监控告警 |
| 每任务生成调用次数 | 对照 `max_calls` |

阈值由业务方在 Stage 1 基线后书面约定；未约定前不得宣称「达标上线」。

---

## 4. 启用 fast + big 长期常驻的门槛

须**同时**满足：

1. fast 承接目标任务后，整体 **p95 延迟明确下降**；  
2. 人工修正率**不超过**约定阈值；  
3. fast→big 升级能覆盖大部分低质量结果；  
4. 双常驻不影响百万行文件处理与稳定性；  
5. 连续 24h 无 OOM、任务锁死、端点频繁重启。

未满足 → 生产保持 **单 big + embed**（或 big only），fast 按需或不上。

---

## 5. 互验保留门槛

仅当「互验发现的**真实错误**收益」>「新增调用 + 人工处理冲突成本」时，在生产保留独立互验；否则仅留评测开关。

---

## 6. Coder-30B A/B 退出条件（Stage 4）

在相同评测集上比较复杂 SQL 执行正确率、延迟、内存：

| 结果 | 动作 |
|---|---|
| 显著优于 27B-FP8 | 可替换 big |
| 互有胜负但内存更优 | 可批处理窗口按需切换 |
| 无明显收益 | 不进生产池 |

禁止 9B + 27B + Coder **三生成模型**长期同时常驻。

---

## 7. 故障与伪高置信验收（必测）

| 用例 | 期望 |
|---|---|
| big 宕机 + 互验任务 | `unverified`，无 consistent |
| big 宕机 + 复杂 SQL | 若走 fast 候选则 `needs_confirm=true` |
| 非法 JSON / schema 失败 | `output_invalid`，不进执行器 |
| 配额耗尽 | `quota_exhausted` + 规则/人工 |
| 熔断打开 | 不再打故障端点，状态可见 |
