## 1. 设计结论

前端 Vue3、后端 FastAPI；源码、构建、接口、职责分离。运行方式按环境区分：

| 环境 | 前端 | API 访问 | Nginx |
|---|---|---|---|
| **开发（F1）** | Vite 容器 `:5173` | Vite 代理 `/api`、`/events` → `api:8010` | 不用 |
| **MVP（F2）** | FastAPI 临时托管 `frontend/dist` | 同源 `/api/v1` | 可不使用 |
| **正式（F3）** | Nginx 容器托管 dist | Nginx 代理 → `api:8010` | **使用（Compose 内）** |

- Nginx 是 **Compose 前端容器**，不是宿主机系统服务。  
- 正式部署：**只映射一个入口**（默认 `127.0.0.1:8080`）；api / worker / writer / vLLM / embed **仅 Docker 内部网络**（expose，不 publish）。  
- 单容器 PoC（00 §1.3）仍可临时映射多端口，**不得当作终态**。

推荐正式拓扑：

```text
宿主机浏览器
   │
frontend/nginx:8080   ← 唯一映射到宿主机（单机绑 127.0.0.1）
   │
   ├─ Vue 静态
   ├─ /api/v1/*  → api:8010
   └─ /events/*  → api:8010（SSE）

Docker 内部网络
   api:8010 · intake-worker · writer
   vllm-fast:8000 · vllm-big:8001 · embedding:7999
```

**embed 地址**：Compose 内部为 **`embedding:7999`**（本拓扑）；PoC 单容器为 **`:8002`**。统一用 `LLM_EMBED_ENDPOINT`，见 [01 embed 端口 SSOT](01-本地模型部署与多模型编排.md)。

## 2. 目标与非目标

### 2.1 目标

1. 开发与部署容器化；不要求宿主机装 Node/Python/Nginx。  
2. 前后端独立开发、测试、构建。  
3. 浏览器**单一同源入口**，生产不依赖 CORS。  
4. API、vLLM、worker、库文件不对宿主机/LAN 直接暴露（正式态）。  
5. 大文件流式落盘；长任务可恢复、可看进度（SSE 优化体验，库内任务状态为 SSOT）。  
6. OpenAPI → 生成前端类型，防契约漂移。  
7. 写操作：鉴权 + version + 幂等 + 冲突 409。  
8. 断网可构建、启动、升级、恢复。

### 2.2 非目标

- 不拆大量微服务。  
- 前端不直连 DuckDB / SQLite / vLLM。  
- Nginx 不做业务逻辑。  
- 第一阶段不上 WebSocket 双向协同。  
- 运行时不从 CDN/npm/pip/远程模型仓下载。

## 4. 开发环境（Phase F1）

### 4.1 拓扑

```text
浏览器 http://127.0.0.1:5173
  → frontend-dev (Vite)
       /api,/events → http://api:8010
```

浏览器不直连 `:8010`。前端业务代码：

```ts
const API_BASE = "/api/v1";
```

**禁止**写死 `localhost:8010`、容器 IP、vLLM 端口。

### 4.2 Vite 代理（要点）

`vite.config.ts`：`/api`、`/events` → `http://api:8010`；`host: 0.0.0.0`；`port: 5173`。

### 4.3 Compose 开发

- `deploy/compose.dev.yml`：`frontend`（dev target）+ `api`（healthcheck `/health/live`）。  
- 模型用 Compose **profile `models`**，普通前端开发可不拉大模型：

```bash
docker compose -f deploy/compose.dev.yml up frontend api
docker compose -f deploy/compose.dev.yml --profile models up
```

示例 YAML 骨架见整理2 §4.3；GPU/writer 细节以 01/03/06 为准。

## 5. MVP 与正式部署（F2 / F3）

### 5.1 MVP（F2）：FastAPI 托管 dist

```text
浏览器 :8010 → FastAPI（/api/v1/* + StaticFiles frontend/dist）
```

适用：单用户本机闭环、可一起重启、暂不需独立静态缓存。  
**禁止**长期用 `python -m http.server` 或 `vite preview` 当正式静态服务。  
迁移 Nginx 时业务代码仍用相对 `/api/v1`，只改镜像与 Compose。

### 5.2 正式（F3）：Nginx 前端容器

- 映射：`127.0.0.1:8080:8080`（禁止无意 `0.0.0.0` 全网卡暴露）。  
- api/worker/writer/vLLM：**expose only**。  
- 多阶段镜像：`node` build → `nginx:alpine` + `nginx.conf`。  
- 离线：`npm ci --offline`；现场不远程 `npm install`。

### 5.3 Nginx 基线（必须项）

| 项 | 要求 |
|---|---|
| `client_max_body_size` | **2g**（= 05 §1.4 `UPLOAD_MAX_BYTES`；解压膨胀另限 500MiB） |
| SPA | `try_files … /index.html`；`index.html` no-cache |
| `/assets/` | 长缓存 + immutable |
| `/api/` | `proxy_pass http://api:8010`；读/发超时约 300s；传 `X-Request-ID` |
| `/events/` | **关闭** `proxy_buffering` / `proxy_cache`；读超时 **1h** |
| 上传缓冲 | 是否关 `proxy_request_buffering` 由大文件实测决定；开启则规划临时盘容量 |

完整 conf 见整理2 §5.3。

### 5.4 正式 Compose 边界

服务：`frontend` / `api` / `worker` / `writer` / `vllm-fast` / `vllm-big`（+ embed）。  
环境变量示例：`META_DB_PATH`、`BIZ_DB_PATH`、`LLM_*_ENDPOINT` 用**服务名**（如 `http://vllm-fast:8000/v1`）。  
健康：api `GET /health/ready`。细节 YAML 见整理2 §5.4。

## 6. API 契约（与 05 对齐）

### 6.1 版本前缀

- **新业务接口**：统一 `/api/v1/*`。  
- **健康检查**（无版本前缀）：`GET /health/live`、`GET /health/ready`。  
- 现有无 `v1` 路径在实现迁移期可双挂；OpenAPI 与前端生成客户端以 **v1 为契约 SSOT**，旧路径标 deprecated。

### 6.2 OpenAPI → 前端类型

```text
FastAPI OpenAPI → openapi-typescript / orval → frontend/src/api/generated
npm run api:generate && npm run api:check   # 不一致则失败
```

生成层不写页面逻辑；`src/api/` 薄适配：统一错误、认证、格式。

### 6.3 错误体与状态码

成功可不强制包 `{ok:true}`（资源即响应）。错误统一：

```json
{
  "error": "...",
  "message": "人可读说明",
  "code": "STAGE_VERSION_CONFLICT",
  "details": {},
  "request_id": "req_…"
}
```

前端按稳定 **`code`** 分支，不解析中文 `message`。  
状态码表见 [05 §3.3](05-安全与API规范.md)（含 201/202/409/422/429/503）；**禁止**把互验冲突、LLM 非法输出一律伪装成 200。

### 6.4 写操作一致性

副作用 API 必须具备（能落地则全开）：

| 机制 | 说明 |
|---|---|
| `Idempotency-Key` | 重复提交同一业务结果 |
| `version` + `expected_status` | 乐观锁；不匹配 → **409** |
| 认证主体 | ops / session；`confirmed_by` 不可伪造 |
| `request_id` | 贯穿 Nginx→API→任务→llm_call→发布 |

confirm 示例见整理2 §11；与 03 §4.7 `release_id` 幂等互补。

## 7. 同步 / 异步 / SSE

| 业务 | 方式 |
|---|---|
| 列表、详情、指标 | HTTP |
| 解析、接入分析、规则重放 | **202** + `task_id` |
| 任务进度、告警 | **SSE**（`/events/…`） |
| LLM 问答 | HTTP 起步；需流式再 SSE |
| 模型加载/切换 | 异步任务 + SSE |
| 双向协同 | **不上** WebSocket（本期） |

202 响应含 `events_url`、`status_url`。SSE 断线后先 `GET` 任务状态再续订。事件不携带完整敏感 prompt。  
**任务状态以 SQLite 为 SSOT**，SSE 仅推送。

## 8. 大文件上传

```text
multipart → 代理 → FastAPI 分块写临时文件 + 增量 SHA256
  → 校验失败删临时 → 成功原子 rename → 入队 → 202
```

- **禁止** `await file.read()` 整文件进内存。  
- 上限与解压限额见 **[05 §1.4](05-安全与API规范.md) 配对表**（原始单文件 2GiB ≠ 解压 500MiB）。  
- 存储名与展示名分离（内部随机 ID）；断连清理；临时 TTL。  
- UI：**上传进度**（XHR）与**解析进度**（任务 SSE）分两段，勿混成一根条。  
- 断点续传：一期不做；常态超 2GiB 或不稳定链路时再议。

## 9. 鉴权（对齐 05 §1.5）

| 模式 | 要点 |
|---|---|
| 单机 | 入口 `127.0.0.1`；危险写仍需 ops；**勿**把长期 ops token 存 localStorage |
| LAN（F4） | viewer / operator / admin；HttpOnly + SameSite=Strict Cookie；后端再校验 |
| CSRF | 同源 Cookie 写接口须 CSRF 或严格 Origin/Referer；**同源≠已防 CSRF** |

## 10. 前端状态与构建（对接 07）

| 状态 | 位置 |
|---|---|
| 列表/详情/任务/模型 | Vue Query（或同等） |
| 用户/权限/偏好 | Pinia |
| 分页/筛选/Tab | URL query |
| 任务真实状态 | **后端库** |
| 表单草稿 | 组件/表单库 |

勿把同一 API 数据同时拷进 Query+Pinia+多组件。刷新靠 `task_id` + URL；表单展示 `version`/更新时间。  
构建：路由懒加载 8 页；Element Plus/ECharts 按需；内容哈希；禁公网字体/CDN/远程脚本。

## 11. 健康检查与可观测性

| 端点 | 含义 |
|---|---|
| `/health/live` | 进程存活（不查全依赖） |
| `/health/ready` | meta + 业务只读 + 必要内部依赖；**big 不可用≠整体 not ready**（功能降级）；writer/meta 不可用则拒写任务 |

贯穿 ID：`trace_id` / `X-Request-ID` / `task_id` / `release_id` → Nginx 日志、API、任务表、llm_call、发布清单、前端错误详情。  
前端默认简明错误 + 可执行动作；可展开 `code`/`request_id`；禁完整堆栈、库路径、敏感 prompt。
