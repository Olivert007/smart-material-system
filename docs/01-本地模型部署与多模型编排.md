### 1.1 模型制品固定（D4，禁止模糊 Q8 估算）

| 角色 | 制品（主选） | 阶段 | 记录项 |

## 4. 任务路由与降级链

生产路由以 **PolicyRouter + TaskPolicy** 为准；**`task_type` 枚举以 [09 §4.1](09-多模型编排策略.md) 为 SSOT**，禁止 LLM 自路由。部署期简表：

```python
# 与 09 TASK_POLICY 对齐（旧名 ask/ask_simple/quality 仅兼容别名，见 §5.4）
TASKS = {
    "profile":         "fast",   # Stage 2+；Stage 1 可 big 或纯规则
    "map_headers":     "fast",
    "summary":         "fast",
    "sql_simple":      "fast",
    "sql_complex":     "big",
    "quality_explain": "fast",   # 可 escalate → big
    "ingest_plan":     "big",
}
```

**普通生成降级（互验不适用）：**

```
big 不可用 ──► fast ──► 纯规则/规则引擎 ──► 落"待人工"，不静默丢
```

降级**不得**提升置信等级（09 §7）。**`sql_complex`（及同等高风险任务）若降级到 fast**：结果必须带 `needs_confirm=true`（及 `degraded: true`），不得自动执行/高置信展示。环境变量见 §1；可用性：`GET /v1/models`。

## 5. 三层编排模式（部署接口骨架）

细则与场景流见 **09**；本节保留实现骨架（对齐 00 D5）：

```
任务
 ├─ ① PolicyRouter：规则/模板 → embed 召回 → fast → 升级 big → 或直接 big
 ├─ ② 任务内协作：
 │     ├─ 级联：fast 草稿 → big 终稿 → 规则校验（Stage 2+）
 │     └─ 互验：两侧真实不同模型；禁止 fallback（Stage 3+，且过 10 §5）
 └─ ③ 降级链（仅普通生成）：big → fast → 规则 → 待人工
```

### 5.1 级联模式（fast 草稿 → big 终稿 → 规则校验）

```
fast 草稿 ──► big 审查并输出完整终稿 ──► 规则/白名单/schema 校验 ──► 执行或待人工
```

- **不再**让 fast 重写终稿。触发与预算见 09。记录草稿/终稿 diff。

### 5.2 互验模式（禁止 fallback）

适用于关键决策。**Stage 3 + [10 §5](10-模型评测与验收.md) 通过前可不启用**（00 D8）。

```
fast 端点真实结果 ─┐
                   ├─ 两端均成功且一致 → consistent（仍可人工推翻）
big 端点真实结果 ──┘
                   ├─ 不一致 → conflict，进人工
                   └─ 任一端失败/降级 → unverified（不得标 consistent）
```

硬约束：互验禁止 fallback；审计真实 `model_id`/revision/endpoint；JSON 字段相等 / SQL 规范化等价。

### 5.3 编排决策表（摘要）

| 任务 | 编排模式 | 说明 |
|---|---|---|
| 常规画像 / 映射 / 总结 | → fast（Stage 2+） | Stage 1 可 big 或规则 |
| 简单问答 | → fast；低置信 escalate | 见 09 |
| 复杂 Text2SQL | big 或级联 | Stage 1 起 big |
| 关键决策 | 互验（无 fallback） | Stage 3+ |
| 质量解读 / 接入建议 | → big；可互验 | 冲突进人工 |
| 表头/主数据候选 | **embed 召回** → 生成/规则 | 多候选仅预填 |

完整 TaskPolicy 见 09 §4。

### 5.4 实现方案（llm.py → 编排模块）

**现状**：`app/llm.py` 仍单端点 `LLM_ENDPOINT`——编排**未落地**。目标拆分见 09 §3（ModelRegistry / PolicyRouter / …）。

**环境变量与端点**：

```python
FAST_ENDPOINT = os.environ.get("LLM_FAST_ENDPOINT",
                  os.environ.get("LLM_ENDPOINT", "http://localhost:8000/v1"))
BIG_ENDPOINT  = os.environ.get("LLM_BIG_ENDPOINT", "http://localhost:8001/v1")
EMBED_ENDPOINT = os.environ.get("LLM_EMBED_ENDPOINT", "http://localhost:8002/v1")
FAST_MODEL = os.environ.get("LLM_FAST_MODEL", "")
BIG_MODEL  = os.environ.get("LLM_BIG_MODEL", "")
```

**任务表与路由（含降级候选链）**：

```python
# task_type SSOT = 09 §4.1；(档位, 超时秒)
TASKS = {
    "profile":         ("fast", 180),
    "map_headers":     ("fast", 120),
    "summary":         ("fast", 60),
    "sql_simple":      ("fast", 120),
    "sql_complex":     ("big",  180),
    "quality_explain": ("fast", 180),  # escalate → big 由 PolicyRouter
    "ingest_plan":     ("big",  180),
    "cascade":         ("both", 300),
    "cross_check":     ("both", 240),
}
# 兼容别名（实现期映射后删）：ask_simple→sql_simple, ask→sql_complex, quality→quality_explain

def route(task):
    grade, timeout = TASKS.get(task, ("fast", 120))
    chain = {"fast": [FAST_ENDPOINT],
             "big":  [BIG_ENDPOINT, FAST_ENDPOINT],
             "both": [FAST_ENDPOINT, BIG_ENDPOINT]}[grade]
    return chain, timeout
```

**统一调用与降级**：普通任务沿候选链；整链失败 → 规则/待人工。降级带 `"degraded": true`，**不得**标高置信。`sql_complex`（等高风险）降到 FAST 时必须 `"needs_confirm": true`（09 §7.3）。

**四个编排接口**（骨架；生产路径以 PolicyRouter 为准）：

```python
def generate(task, msgs, grade=None, temperature=0.0, max_tokens=1024):
    ...

def cascade(task, msgs):
    # ① fast 草稿 → ② big 终稿 → ③ 规则校验（禁止再让 fast 定稿）
    draft = generate(task, msgs, grade="fast")
    final = generate(task, msgs + [draft, REVIEW_PROMPT], grade="big")
    if not rule_validate(final):
        return {"ok": False, "error": "rule_validate_failed", "draft": draft, "final": final}
    log_diff(task, draft, final)
    return {"ok": True, "result": final}

def cross_check(task, msgs):
    r_fast = generate_strict(task, msgs, endpoint=FAST)  # 失败 → unverified
    r_big  = generate_strict(task, msgs, endpoint=BIG)   # 不得降到 FAST
    if r_fast.failed or r_big.failed:
        return {"ok": False, "unverified": True, "fast": r_fast, "big": r_big}
    if consistent(r_fast.text, r_big.text, task):
        return {"ok": True, "result": r_big.text, "conflict": False,
                "model_ids": [r_fast.model_id, r_big.model_id]}
    return {"ok": False, "conflict": True, "fast": r_fast, "big": r_big}
```

**一致性判定 / 结构化输出**：同前——JSON 字段相等；SQL 规范化等价；推荐 `guided_json`。

**审计落库**：字段以 [09 §8.3](09-多模型编排策略.md) 为扩展 SSOT；兼容列仍可含 `prompt_version` / `cost_tokens`（§5.6–5.7）。

**兼容封装**：`text2sql → sql_simple|sql_complex`（经 `classify`）、`suggest_mapping → map_headers`（前挂 embed）、`ask_summary → summary`、质量解读 → `quality_explain`。

**复杂度判定 `classify(question)`**：多表/窗口/时间/子查询等信号；0~1 → `sql_simple`(fast)；≥2 → `sql_complex`(big)；关键 → 互验/级联。细则进 TaskPolicy（09）。

### 5.5 模型状态枚举与容错解析层（08-07 新增）

参考成熟本地模型项目（excel-analysis-api）的做法：**"已配置"不等于"可用"，"调用成功"不等于"输出可用"**——状态必须粒度到"这次调用到底发生了什么"，且模型输出格式变体多，需要容错解析 + schema 强制校验兜底。

**调用状态 9 态枚举**（每次 LLM 参与的任务都产出，落 `llm_call` 审计）：

| 状态 | 含义 |
|---|---|
| `model_not_configured` | 未配置模型（端点缺失） |
| `configured_not_invoked` | 已配置但未调用（本次请求未触发模型） |
| `local_model_configured_not_invoked` | 本地模型已配置但未调用（字典/规则命中直接出结果） |
| `llm_analysis_available` | 模型成功返回且通过 schema 校验（正常态） |
| `llm_invocation_failed` | 调用失败（端点不可达 / 超时 / 非 2xx） |
| `llm_output_invalid` | 调用成功但输出未通过 schema/Pydantic 校验 |
| `local_model_unavailable` | 本地模型探测失败（vLLM 未起 / 崩溃） |
| `local_model_output_invalid` | 本地模型输出无效（容错解析后仍非法） |
| `unsupported_model_provider` | 不支持的模型提供方 |

**每次调用的响应字段**（前端/治理中心据此展示"这次结果来自哪、质量如何"）：

| 字段 | 说明 |
|---|---|
| `model_request_attempted` | 是否尝试过调用模型 |
| `model_invoked` | 实际调用模型（fast / big / degraded） |
| `output_available` | 是否有可用输出（通过校验才算） |
| `fallback_reason` | 降级/失败原因（端点不可达 / 超时 / 输出非法 / 未配置…） |
| `evidence_digest` | 模型看到的证据摘要（抽样范围/行数/列数/表头数），防止"基于不完整证据下结论"无法追溯 |

**容错解析层 `parse_model_output`**（模型输出格式变体多，先归一化再校验）：

```
模型原始输出
  │ ① 去 markdown JSON fence（```json ... ```）
  │ ② 截取首个 {…} 平衡对象；若为裸数组按 schema 包装
  │ ③ 值归一化：91% → 0.91、yes/true/1 → true、枚举别名 → 规范枚举、去多余空白
  ▼
④ 必须过 schema/Pydantic 校验 —— 字段与预期 schema 对齐
  ├─ 通过 → llm_analysis_available，输出可用
  └─ 失败 → llm_output_invalid，输出丢弃，不采用
```

- **容错 ≠ 放行**：归一化只解决"格式变体"，**输出仍必须过白名单/schema 校验**（05 §1 LLM 产出校验）才具执行资格——这是对模型幻觉与格式漂移的双重兜底。
- **失败显式降级，不伪造 AI 输出**：校验失败时返回 `output_available: false` + `fallback_reason`，走降级链（§4），落"待人工"，绝不把非法输出当正常结果静默使用。
- 与 07 §3.7 联动：卡片状态展示最近一次调用状态（9 态徽标），可区分"配置了但没调用"与"调用了但失败/输出非法"。

### 5.6 提示词集中管理（08-07 新增）

**问题**：级联/互验/画像/schema/few-shot 等 prompt 模板散落各模块与代码，**改了不可追溯、影响无法评估**——同一条 prompt 的改动可能改变所有后续识别结果，必须与规则字典一样可版本化、可回滚。

**`prompt_template` 表（meta.sqlite）**：

| 列 | 说明 |
|---|---|
| `template_key` | 模板标识（如 `map_headers` / `sql_generate` / `sql_review` / `sql_finalize` / `profile_sheet` / `quality_explain`） |
| `version` | 版本号（变更 +1，历史留存） |
| `system_prompt` / `user_prompt` | 模板正文；动态部分用占位符（`{{schema}}`、`{{fewshot}}`、`{{evidence}}`） |
| `parameters` | 占位符清单与来源（运行时由各模块注入） |
| `task_type` | 适用任务（对应 §4 TASKS） |
| `status` | `active` / `deprecated` |
| `confirmed_by` / `created_at` / `updated_at` | 审计 |

**机制**：
- `llm.py` 启动时加载全部 active 模板到内存；模板版本变化（版本表变更）触发热更新重载。
- **变更走 04 §6.7 规则变更治理**：dry-run 预演（在历史证据副本上试跑，看映射/SQL 差异 diff）→ 冲突/影响评估 → 人工确认生效（version+1）；改错一键回滚。
- **审计回放**：`llm_call` 记录 `prompt_version`，可精确回放"某个结果是用哪个 prompt 版本产出的"——排查识别漂移时直接定位模板版本。
- 与 few-shot / 画像 / schema 注入的关系：**模板集中管，上下文动态拼**——模板含占位符，few-shot 示例、表画像、schema 摘要都是运行时注入的上下文，不混入模板正文。

### 5.7 LLM 成本与调用控制（08-07 新增）

**问题**：级联 3 次 / 互验 2 次 / 采样仲裁 2 次 / 降级重试会放大调用次数——批量接入大量文件时 LLM 开销失控（本地推理吃显存与算力，且拖慢队列），必须有配额、熔断与统计。

**调用预算（配额）**：

| 层级 | 规则 |
|---|---|
| 任务类型配额 | 每类任务每日调用次数上限（如 `ask ≤ 500`、`map_headers ≤ 2000`），超额 → 该任务强制走规则/字典 + 待人工 |
| 单文件预算 | 一次接入的模型调用数封顶（画像 1 + 映射 + 质量 1 + 建议互验 2 + 核对 1，合计约 6~8 次）；超预算标"预算耗尽"，剩余步骤靠规则 + 人工 |
| 批量队列限流 | `/api/files/batch` 并发上限（如 2 个文件同时跑模型）；队列内模型调用总量日上限，防批量任务打满整天 |

**熔断**：
- 连续失败熔断：同一任务连续 N 次 `llm_invocation_failed` / `llm_output_invalid`（如 5 次）→ 熔断 30 分钟，期间直接走规则/字典 + 待人工，不再打模型（避免对同一坏模型反复重试）。
- 配额熔断：日配额耗尽 → 降级到"规则优先 + 人工"，状态在 07 监控页可见，人工可手动解除。
- 熔断与 9 态（§5.5）联动：熔断中的调用状态显示 `llm_invocation_failed` + `fallback_reason="quota_exhausted/circuit_open"`。

**成本统计**：`llm_call` 增加 `cost_tokens`（prompt+resp 总 token）列；07 监控页展示每日调用次数、token 量、降级/熔断次数趋势——**成本可量化**，超阈值提示优化编排（如把互验改为仅关键任务）。

**配置**：环境变量 `LLM_DAILY_QUOTA` / `LLM_TASK_QUOTA` / `LLM_CIRCUIT_BREAK_N`，配额使用落 `meta.sqlite.llm_quota` 表（按天重置）。

## 7. 已知容量与限制

| 项 | 值 |
